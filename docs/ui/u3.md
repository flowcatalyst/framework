# The orders application: U3 results (2026-10-15)

Milestone U3 of [`../go/ui.md`](../go/ui.md) section 17: an example single-page application on the
shared UI package, on a **real backend**: the Java `examples/orders-demo`, which serves it from its
jar with the strict CSP, signs users in with the framework's sessions (M4c) and answers the typed
orders API (MO). Exit: "list, drawer and add-line form against the real server, validation errors on
fields, E2E green". Components and partials are in [`u1.md`](u1.md) and [`u2.md`](u2.md); this page is
what building a real application on them found.

## Results

- `tests/e2e`: **28 passed** (auth 9, orders 11, axe 5, SPA serving 3), 4 screenshot cases skipped
  without `SCREENSHOTS=1`. `pnpm check` is green (gallery e2e 90 passed, api-runtime 37, ui 49).
  Java: `OrdersApiTest`, `OrdersConformanceTest`, `OrdersOpenApiTest`, `OrdersDemoTest` (17) and the
  new `OrdersSpaTest` (3).
- **Every test runs a CSP monitor** (`e2e/fixtures.ts`): no `securitypolicyviolation`, no console
  message about the policy, no request to another origin, no uncaught page error. The demo's strict
  policy is the one `@flowcatalyst/ui/csp` builds (asserted equal in `spa.spec.ts`).
- **Axe at WCAG 2.2 AA, strict, zero violations**: the list (empty and filled), not found, signed out,
  sign-in failed, not permitted, the drawer, the new-order and add-line dialogs with errors, the
  discard and the confirm dialogs, a toast over the drawer, the filters popover; light and dark;
  desktop and 390 px. G2 (since fixed) was the one exception.
- Real-browser findings the in-page gallery could not give: the whole sign-in round trip (anonymous
  visit, `/auth/login?returnTo=`, provider, callback, cookie, back to the deep link), an ended session
  noticed by the next call and by window focus, sign-out and the platform's post-logout redirect, a
  viewer's read-only UI and the server's `403` for the same write, a user with no role, a refused
  sign-in, a `409` business rule shown in the dialog, a stale cancel, `503`, `403` and an offline fetch
  as toasts, hashed assets `immutable`, a stale chunk a `404` never the shell.
- hey-api's `int64` Zod setting from U2 held: `unitPriceCents` leaves the form as a JSON number
  (`{"sku":"PUNCH-CARDS","quantity":500,"unitPriceCents":3}`, asserted).

## Design notes

- **Where the application lives.** The pom's resource (`web/dist` under `fw-spa`) and the committed
  `openapi.json` are in `examples/orders-demo/web/`; the application's source is in the UI workspace
  (`ui/apps/orders`) so that `pnpm check` lints, typechecks, drifts and tests it with the kit, and its
  Vite build and generator point at the demo's folder. An application in another repository has its
  own `web/` with the same `package.json` shape and `link:` dependencies (README).
- **Forms with variant fields: one component per variant.** A parent holds the one `v-if` chain on
  the kind; each variant component takes its variant as the model type (`Extract<Source, { kind: "HTTP" }>`)
  and owns its fields. A single long template with a `v-if` per variant loses vue-tsc's narrowing
  part-way down (Camel feedback j); casting hides mistakes. Example in the guide.
- **`/orders` is a client route** and the server has none under that first segment (its API is
  `/api/orders`): contract section 5, checked by `OrdersSpaTest` and `spa.spec.ts`.
- **Permissions show and hide, the server decides.** The sidebar entry, `New order`, `Add line` and the
  cancel section follow `session.can(...)`; a viewer's write is refused by the server (`403`) in the
  same test. A user with no role goes to `Not permitted` (route `meta.permission`), not to a broken list.
- **No timers on the session.** The session is read once and again on window focus (a test dispatches
  the event after ending the session on the server); a `401` on any call starts sign-in.
- **The cancel flow** is: type a reason in the drawer (the API requires one), `Cancel order…` asks
  (`useConfirm`, `Keep order` is the focused answer), a `409` (changed meanwhile) is a toast and the
  drawer reloads the order. Typing a reason and leaving asks "Discard changes?" through `useDirtyForm`.
- **The test provider changes who signs in** (`/control/sign-in-as?roles=`), so one backend serves clerk,
  viewer and no-role users; `freshData()` truncates the orders before each test. One Playwright worker:
  the tests share one database.

## Not verified

- Only Chromium (as U0). Firefox and WebKit not run.
- A real platform: the sign-in is against `TestOidcProvider`, which is shaped like the platform
  (sessions contract section 9). The platform must have `{public-base-url}/auth/callback` and
  `{public-base-url}/signed-out` (post-logout redirect) registered for the login client; nothing here
  proves that.
- The Vite dev proxy is verified by hand once, not in the suite.
- The platform being down at sign-in in a real browser: the framework keeps the discovery document for the life of the process, so the shared e2e backend cannot be made to fail at discovery; `PLATFORM_UNAVAILABLE` for a navigation is proven in Java (`LoginFailureNavigationTest`, cold) and its sentence in the gallery, not in the orders e2e. Go has no sessions yet, so the new vector runs on Java only.
- Production TLS (`__Host-` cookies over https): the suite runs `APP_ENV=test` over plain http.
- The Go orders-demo is not built, so the Go side of "the same SPA on both backends" is untested; the
  application only depends on the committed `openapi.json`, the auth endpoints and the cookie rules.
