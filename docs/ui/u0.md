## Question 1: Nuxt UI under the strict CSP

**Result: yes, with four measures, all in `@flowcatalyst/ui`.** The gallery is built, served by
`apps/gallery/scripts/serve-csp.ts` with exactly the strict policy of the static-assets contract
section 7 (`style-src 'self'`, no `'unsafe-inline'`, no nonce, no style hash):

```
default-src 'self'; script-src 'self' 'sha256-xo9261yOpFM47x0zwjr2iUF9sFaw/YoSkqnnzaDaOC8=';
style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'none';
base-uri 'none'; form-action 'self'; object-src 'none'
```

plus `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, `Cross-Origin-Opener-Policy` and
`Permissions-Policy`. Playwright (Chromium 153) records every `securitypolicyviolation` event from
before the first script, every console message about the policy and every request to another
origin, and requires all three to be empty after: the dashboard shell (`UDashboardGroup`,
`UDashboardSidebar`, `UDashboardPanel`, `UDashboardNavbar`, `UNavigationMenu`), colour-mode switching
in both directions, a stored dark choice on reload, system dark mode, `UModal` open and Escape,
`USlideover` open and Escape, `UPopover` (click and hover), `UTooltip`, `UDropdownMenu` (select an
item), a `useToast` toast, `UForm` with a Zod 4 schema (validation error shown, then submit),
`USelect`, `USelectMenu` (multiple), `UInput`, `UTextarea`, `UInputNumber`, `URadioGroup`,
`UCheckbox`, `USwitch`, `UInputDate` (range, keyboard edit), `UTable`, `UPagination`, `UTabs`,
`UAccordion`, `UAlert`, `UAvatar`, `UKbd`, `UProgress`, `USkeleton`, `UCard`, `UEmpty`, `UBadge`, and
`UDrawer` open. No request leaves the origin (icons are bundled, the font is self-hosted).

What would have violated the policy, found by reading the sources and confirmed in the browser, and
what the package does about it:

| Source | What it does | Measure |
|---|---|---|
| Nuxt UI's runtime colour plugin (`runtime/plugins/colors.js`, installed by `@nuxt/ui/vue-plugin`) | writes `--ui-color-*` and `--ui-primary` etc. into an inline `<style>`, once directly and once through `@unhead/vue` | `flowcatalystUi()` (Vite plugin) replaces the module with a no-op that imports the same CSS, generated at build time from the same colour map, as a real stylesheet. A Nuxt UI runtime plugin it does not know fails the build |
| `vaul-vue` (under `UDrawer`, which `UDashboardSidebar` and `USidebar` import, so it loads on every page with the dashboard shell) | appends a `<style>` when its module loads (vite-plugin-css-injected-by-js) | the Vite plugin lifts that CSS into the stylesheet at build time (dropping one rule that browsers ignore and lightningcss refuses: `[data-vaul-handle-hitarea]:{...}`); an injector it cannot parse fails the build |
| VueUse `useColorMode` with `disableTransition: true` (Nuxt UI's colour mode and `UColorMode*` components) | inserts a `<style>` on every mode switch | Nuxt UI's `colorMode` is off; `useColorMode()` and `FwColorModeButton` in the package call VueUse with `disableTransition: false`. Lint forbids the `UColorMode*` components |
| Zod 4 | probes `new Function("")` (caught, but reported as a `script-src` violation) the first time an object schema is built | `z.config({ jitless: true })` before any schema exists (`apps/gallery/src/zod-csp.ts`, imported first); `@flowcatalyst/api-runtime` takes this over at U2 |
| no flash of the light theme | needs a script before the first paint | one inline snippet (`COLOR_MODE_SNIPPET`), written into `index.html` by the Vite plugin and allowed by its hash (`COLOR_MODE_SNIPPET_SHA256`, both exported by `@flowcatalyst/ui/csp`; a unit test ties them) |
| Vite inlining small assets | a font under 4 KiB would become a `data:` URL, refused by `font-src 'self'` | the Vite plugin never inlines fonts |

Known to break the policy and kept as probes, so a fix upstream is noticed (each probe test asserts
the violation still happens): **`UBanner` with an `id`** (persistent dismissal adds an inline script
and style through `useHead`; without `id` it adds nothing) and **`USplitter`** (Reka UI puts the drag
cursor in an inline `<style>` while a handle is dragged). Lint forbids both components outside the
probes. Not used by the gallery and not exercised: `ProseImg` and `UChangelogVersions` (motion-v
inserts styles), Vue's `defineCustomElement` (shadow-root styles).

Styles set from script (`element.style`, Vue's `:style` bindings, Floating UI positioning, Reka's
visually hidden copies) are CSSOM writes, which `style-src` does not restrict: no violation was seen.
A static `style="..."` attribute in a template could end up in markup Vue inserts with `innerHTML`
(static hoisting); lint forbids it (`vue/no-static-inline-styles`).

**For the contracts:** the static-assets contract's strict policy can become the default (owner,
2026-10-14: "if U0 passes") with one script hash, the snippet's above, and no style source besides
`'self'`, provided the SPA is built with `flowcatalystUi()` and sets Zod's `jitless`. Chromium only:
Firefox and WebKit were not run.

## Question 2: hey-api with `const` and `oneOf` + `discriminator`

`samples/openapi/openapi.json` is hand-written to the OpenAPI contract's rules (closed records,
"may be absent" as not required, the `Error` component and shared response, implied statuses,
security schemes, `x-fw-permission`, the sessions contract's `AuthSession`/`AuthLogout` components,
a sealed `Source` with a discriminator, a cursor page, constraints). Generated with `@hey-api/openapi-ts`
0.99.0 and the contract's configuration unchanged (`typescript` with `enums: "javascript"`,
`client-fetch`, `sdk` with `validator: false`, `zod` with `compatibilityVersion: 4`). Checked by
`src/type-checks.ts` (compile-time assertions under the strict settings) and `test/zod.test.ts`:

| Question | Result |
|---|---|
| `const` in TypeScript | **literal types**: `loggedOut: true`, `mode: 'fetch-metadata'`, `authenticated: false` |
| `const` in Zod | `z.literal(true)`, `z.literal('fetch-metadata')` |
| `oneOf` without `discriminator` (`AuthSession`) | TypeScript union that narrows on `session.authenticated`; `z.union([...])` |
| `oneOf` + `discriminator` (`Source`) | TypeScript `({kind: 'database-poll'} & SourceDatabasePoll) \| ...`, exhaustive `switch` compiles; `z.discriminatedUnion('kind', [...])` |
| `enum` | literal unions (no TypeScript `enum`; `erasableSyntaxOnly` holds) |
| "may be absent" | `x?: T`, without `\| undefined` |
| SDK | one function per operation with typed `path`, `query` (arrays included), `body`; errors typed per status with `Error` |
| Zod constraints | `pattern`, `minLength`, `maxLength`, `minimum`, `maximum`, `maxItems`, `format: date` and `date-time` enforced |
| not enforced by Zod | `additionalProperties: false` (`z.object` strips unknown keys instead of refusing them), `uniqueItems`, `format: decimal` and `duration` (plain strings) |

So the sessions contract's `const` form stands; the one-value `enum` fallback is not needed. Notes for
U2 and the emitters: the type named `Error` (the contract's component name) shadows the global
`Error` in files that import it, so import it under another name; the SDK attaches `security` (a
cookie `apiKey`, a bearer scheme) to every operation, and `@flowcatalyst/api-runtime` must not
configure an `auth` callback, so the browser's cookie is the only credential, as sessions section
4.5 requires. The platform's 0.93.1 was not run; 0.99.0 is the pinned version.

## Strict TypeScript

`ui/tsconfig.base.json` is [`../go/ui.md`](../go/ui.md) section 3.1 as written, plus
`allowArbitraryExtensions` and `composite`, with `vueCompilerOptions.strictTemplates`.
`exactOptionalPropertyTypes` and `verbatimModuleSyntax` **work with Nuxt UI's prop types**; vue-tsc
3.3.12 checks unknown props, unknown events and prop types in templates (each checked by breaking a
template on purpose). The exceptions, both scoped and recorded in `ui/README.md`:

1. **hey-api's bundled fetch client** (`src/api/client`, `src/api/core`) fails `exactOptionalPropertyTypes`
   in 12 places, so a generated `src/api/` folder is its own project reference without that flag.
   `types.gen.ts`, `sdk.gen.ts` and `zod.gen.ts` compile with it, and code importing the folder reads
   it under the full settings (an explicit `endSessionUrl: undefined` is still an error).
2. `vueCompilerOptions.dataAttributes: ["data-*", "aria-*"]`: `strictTemplates` otherwise reports
   `aria-label` on a Nuxt UI component as an unknown prop (fallthrough attributes are not typed).

What the flag costs in templates (no exception; written the strict way): a `v-model` value must not
be able to hold `undefined` when the Nuxt UI prop is `modelValue?: T` (form state holds `""`, the
request maps it); `UTable`'s `v-model:sorting` cannot be typed (prop `sorting?: SortingState`, event
`SortingState | undefined`) and is split into `:sorting` and `@update:sorting` (`FwListPage` owns
this once at U2); `UCheckbox` emits `boolean | "indeterminate"`. Types come from
`@nuxt/ui/components/X.vue` and from `@nuxt/ui` (`FormSubmitEvent`, `FormErrorEvent`).

Lint is typescript-eslint `strictTypeChecked` with the project service on `.ts` and `.vue`, plus the
rules of section 3.2 and two more (`vue/no-static-inline-styles`, restricted Nuxt UI components). Two
things make type information work in `.vue` files without a Vue-aware TypeScript server:
`allowArbitraryExtensions` (so plain TypeScript reads Nuxt UI's `.d.vue.ts` declarations; `TableColumn`
callbacks are typed in lint) and a `*.vue` module shim for the application's own components (typed
as `DefineComponent`, never `any`; vue-tsc never uses it). Layout rules of eslint-plugin-vue are off
(formatting is oxfmt's; oxfmt itself is not installed yet).

## Theme

`@flowcatalyst/ui/theme/kit.css` copies the kit's tokens (light and dark, the navy and accent
palettes, the font stacks) and maps them as section 11 says: `--ui-primary`, `--ui-error`,
`--ui-success`, `--ui-info`, `--ui-warning`, `--ui-text`, `--ui-text-muted`, `--ui-text-toned`,
`--ui-bg` (card), `--ui-bg-muted` (page), `--ui-border`, `--ui-border-accented` (control borders) and
`--ui-radius: 2px`, outside cascade layers so they win over Nuxt UI's defaults whatever the bundle
order. Aliases: primary emerald, success green, info sky, warning orange, error red, neutral slate;
secondary keeps Nuxt UI's blue (the kit has none). A unit test compares every copied value with
`ui-kit/theme/tokens.css`. The text scale (12.6 px, `defaultVariants.size`) and the navy sidebar are
left for U1 and U2 as planned.

**axe** (WCAG 2.2 AA tags): the empty gallery (overview page with the shell) has **no violation** in
light and dark, at 1280 px and 390 px. The component pages are clean in dark; in light, four colour
pairs that come straight from the kit's light tokens fail AA 4.5:1, and the test tolerates exactly
these pairs and nothing else, for an owner decision on the tokens:

| Pair | Where | Ratio |
|---|---|---|
| white on `--primary` emerald-600 `#059669` | solid primary: the active tab (the solid primary button has the same computed pair; axe lists it under "incomplete", not as a violation) | 3.76 |
| `--success` green-600 on its 10 % tint | subtle success badge | 2.95 |
| `--info` sky-600 on its 10 % tint | subtle info badge | 3.61 |
| `--muted-foreground` slate-500 on Nuxt UI's `bg-elevated` | inactive tab label | 4.34 |

## Section 10 rows checked at U0

- **date-range:** `UInputDate` with `range` renders a start and an end and edits them by keyboard
  (`@internationalized/date` values) under the CSP: covered as planned.
- **dirty-form:** `UForm`'s `dirty` means "a field had input since the last submit", not "differs
  from the initial values" (typing a change and typing it back leaves it `true`): `useDirtyForm`
  (U2) keeps the platform's snapshot comparison.
- Found on the way, for U2: **`UForm` 4.11.3 drops a submit** made while the validation started by
  an input event is still running (no `submit`, no `error` event; a second click submits);
  `FwFormDialog` must not lose it. `UForm` also leaves native constraint validation on, so an
  `<input type="email">` can block the submit before Zod runs; the gallery's form sets `novalidate`.
  `UDashboardNavbar`'s `title` renders an `<h1>`, a second one next to `FwPageHeader`'s; `FwAppShell`
  must not pass it.

## Section 5 points

- Explicit imports (`components: false`, `autoImport: false`) work; `@nuxt/ui/components/X.vue` gives
  full prop types in vue-tsc and in lint.
- Icons: `icon.clientBundle.scan` bundles the literal names in the application's files and Nuxt UI's
  own; the package's icons are listed (`fcIcons`, a unit test checks the list against its sources)
  because the scan reads only the application's root. The application must install
  `@iconify-json/lucide` itself (the bundler resolves it from the application root).
- Nuxt UI writes its theme types to `node_modules/.nuxt-ui` from the Vite config hook, so `pnpm build`
  runs before `vue-tsc` (the package resolves its Vite config to write them; it has no build output).
- Consumption by `link:` was tried with a scratch application outside the repository: it builds, one
  Vue copy in the bundle, vue-tsc clean under the strict settings, the package's Tailwind classes
  (`@source` in `kit.css`) and icons present.
- pnpm needs its internal hoisting (`node_modules/.pnpm/node_modules`): Nuxt UI's declarations import
  `vue`, which it does not declare, and with `hoistPattern: []` every Nuxt UI component types as
  `any` without an error. Only public hoisting is off.
