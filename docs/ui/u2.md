## `@flowcatalyst/api-runtime`

```ts
// main.ts: the FIRST import (it sets Zod to jitless before any schema exists)
import { createApiRuntime, installSessionGuard } from "@flowcatalyst/api-runtime";
import { client } from "./api/client.gen";

const api = createApiRuntime({ clients: [client] });
installSessionGuard(router, api.session, { notPermitted: () => "/not-permitted", landing: () => "/profile" });
createApp(App).use(router).use(ui).use(flowcatalystUi, { api }).mount("#app");
```

| Part | What it does (sessions contract 4.5, OpenAPI contract 11) | Test |
|---|---|---|
| `configureClient` | `baseUrl: ""` (same origin, overriding a generated one), `credentials: "same-origin"`; **never** an `auth` callback, `Authorization`, `Cookie` or CSRF header; JSON bodies keep the SDK's `Content-Type`, a body-less POST (logout) sends none; a 401 starts sign-in; a 403, a 5xx or a failed `fetch` (not an abort) is reported to failure listeners; configuring a client twice replaces its hooks | `client.test.ts` with the generated orders client and a fetch double |
| errors | `ServiceError` `{status, error, message, details}` from whatever the SDK returns (an envelope, a proxy's HTML, a network failure); `ApiRequestError` for code that throws; `fieldErrors` reads a 400's details (`field: "CODE: message"`); the generated component named `Error` is renamed on import and never re-exported | `errors.test.ts`, `entry.test.ts` |
| `applyServiceError` | puts the field errors on a `UForm` and returns the form-level message; a field the form does not show is kept in the message, not lost | `errors.test.ts` |
| session | `GET /auth/session` once at start (concurrent callers share the read) and again on window **focus**, **never on a timer**; anonymous: navigate to `loginUrl?returnTo=<path+search+hash>` (percent-encoded); expired while open: back to sign-in; `logout()` posts, then navigates to `endSessionUrl` or the signed-out page, and does not navigate when the server refused | `session.test.ts` (fake timers: 8 h without a read) |
| `installSessionGuard` | every route needs a session unless `meta.public`; `meta.permission` with the platform's wildcard rule; a deliberate navigation goes to not-permitted, an automatic landing to `landing`; an unreadable session cancels and reports | `session.test.ts` with vue-router's memory history |
| Zod | `z.config({ jitless: true })` in the entry's first import (`zod-config.ts`); the gallery's own copy is gone | `entry.test.ts`; the gallery's CSP checks |
| generated auth client | `src/generated/auth` from `conformance/openapi/auth.json` (committed, drift-checked); `getAuthSession`, `logout`, the `AuthSession` union narrowing on `authenticated` | `session.test.ts` |

The session reads go through the generated client, so `createApiRuntime` is the only place an
application wires authentication; `@flowcatalyst/ui` reads it through the plugin (`useSession`,
`usePermissions`, `FwAppShell`'s user menu and navigation filter).

## Generation for any application, and int64

`fwOpenApiConfig({ input, output })` (`@flowcatalyst/api-runtime/openapi-ts`) is the contract's plugin
list with two settings the build found necessary; `ui/README.md` has the application's config, the
`api:drift` script (a **new** generated file fails it too, which plain `git diff` misses) and the
tsconfig for the generated folder. The workspace runs it for three folders (`pnpm api:drift`): the
runtime's auth client, its orders test fixture and the gallery's orders client.

1. **`@hey-api/client-fetch` gets `baseUrl: false`.** With the contract's configuration, hey-api 0.99.0
   reads the bare input `openapi.json` as a host and writes `createConfig({ baseUrl: 'openapi.json' })`,
   so every call would go to `openapi.json/api/...` relative to the page (`generate.test.ts` shows both
   outputs; an input with a slash in it does not trigger it). `configureClient` also sets `baseUrl: ""`
   at run time.
2. **int64 stays a number.** For `format: int64` hey-api writes `z.coerce.bigint()` while the
   TypeScript type it writes is `number`; a `UForm` hands the submit handler the schema's output, a
   BigInt, and `JSON.stringify` throws ("Do not know how to serialize a BigInt"). The config passes the
   Zod plugin a number resolver (`~resolvers.number`, hey-api's documented hook) that writes `z.int()`
   with the declared bounds as plain numbers for `int64`/`uint64`; `z.int()` accepts safe integers
   only, which is the contract's own rule ("number, exact only below 2^53: ids are strings").
   Proof: `int64.test.ts` parses `AddLineBody` from the generated `zod.gen.ts` of
   `conformance/openapi/orders-demo.json` (`unitPriceCents` 1999 stays a number, serialises, bounds,
   fractions and strings refused) and posts it through the generated SDK; `generate.test.ts` runs the
   generator both ways and checks the contract's configuration writes
   `z.coerce.bigint().gte(BigInt(0)).lte(BigInt(100000000))`, the package's `z.int().gte(0).lte(100000000)`
   (byte-equal to the committed fixture); in the browser, the gallery's Add line dialog posts
   `{"sku":"WIDGET-9","quantity":1,"unitPriceCents":1999}` to a fake server that reads it with
   `JSON.parse` (`orders.spec.ts`).

Both are **contract findings**: section 11's configuration needs these two settings (not changed by
this step; contract section 11 was amended with both on 2026-10-14).

**exactOptionalPropertyTypes and consumption as source.** hey-api's runtime folders (`client/`,
`core/`) still fail the flag (U0). Because applications compile `@flowcatalyst/api-runtime` from
source, a consumer's `vue-tsc` would compile those files under its own settings and fail; each consumer
therefore references `packages/api-runtime/tsconfig.generated.json` (a composite project that emits
declarations for exactly those folders, without the flag), so they are read through declarations.
`types.gen.ts`, `sdk.gen.ts`, `zod.gen.ts` and `client.gen.ts` compile with the flag on.

**The lost submit (u0.md).** It did not reproduce in the dialog (its footer does not move when a field
error disappears the way the U0 page's button did), but the dialog guards it anyway: the submit button
keeps the focus in the field through `mousedown`, so no blur validation can reflow the dialog between
press and release. Doing so exposed a real data loss: `UInputNumber` (Reka's `NumberField`) commits the
typed text **on blur or Enter**, so a value typed and submitted at once arrived as the old value (0).
The dialog therefore blurs the focused field itself after the click and submits on the next tick;
`orders.spec.ts` types the price and clicks Submit with no blur in between and asserts the posted
body. Any form that submits programmatically while a number field has focus has the same problem.

## Findings for other documents

- **`returnTo`:** the sign-in navigation uses the sessions contract's parameter, `returnTo` (the work
  order said `return`).
- **Cursor pages:** the orders example's `PageOrderSummaryView` has `items` and `nextCursor` but no
  `hasMore`, unlike the `CursorPage` of the OpenAPI fixture and [`../go/ui.md`](../go/ui.md) section
  6.2; `useCursorPagination` accepts both.
- **`listOrders` has no search parameter:** the gallery's search narrows the loaded page in the
  browser (`UTable`'s global filter since the revision); a real list needs a `q` query parameter in
  the operation.
- The U0 sample now generates with `fwOpenApiConfig` (its committed `client.gen.ts` lost the bogus
  `baseUrl`).

## Not verified

**No running backend.** Every call in the gallery goes to an in-page fake server
(`apps/gallery/src/fake-server.ts`) that answers the document's shapes and the error envelope; the
generated client, the configured runtime and the Zod schemas run for real in the browser, but the
Java orders example and the real `/auth/*` endpoints were not called (U3 does, on the Java orders
demo, then U4 the session pages). The 401-to-sign-in navigation and the focus re-read are unit-tested,
not exercised against a server. The response validation run of section 11 (Zod on responses in E2E)
is U3. Firefox and WebKit were not run.
