`@flowcatalyst/ui`, each with its gallery entry and checks. Built on U0 ([`u0.md`](u0.md), commit

## CSP result per component

Every test ends with `csp.expectClean()`: no `securitypolicyviolation`, no console message about the
policy, no request to another origin, no uncaught page error. **Every component above, every partial
and every page is clean under the strict policy**, with the overlays open and after the interactions
the tests make (Chromium 153). Nothing new needed a measure in the Vite plugin. The U0 probes stand
(`UBanner` with an `id`, `USplitter` drag) and are still asserted to violate it. One thing to know:
icons named only in `.ts` files are not found by Nuxt UI's scan and would be fetched from the Iconify
API (a foreign request the CSP blocks); the package lists its own (`fcIcons`, checked by a unit test)
and the gallery passes its sidebar icons to `nuxtUiOptions({ icons })`.

## Accessibility

Zero axe violations at WCAG 2.2 AA except **colour pairs that come straight from the kit's tokens**,
which the test tolerates exactly (pair by pair, `apps/gallery/e2e/axe-tools.ts`) for the owner's
decision:

| Theme | Pair | Ratio | Where |
|---|---|---|---|
| light | white on `--primary` emerald-600 | 3.76 | solid primary button and tag |
| light | `--primary` on white, on its 10 % tint | 3.76, 3.4 | link and outline primary (Filters button, Clear filters), soft/subtle |
| light | white on `--success` green-600, `--info` sky-600, `--warning` orange-600 | 3.30, 4.10, 3.56 | filled tags and badges (the kit's tags are filled) |
| light | the same three as text on white (and at 90 % opacity in alert descriptions) | 2.9 to 4.1 | outline badges, alerts |
| light | `--destructive` red-600 on its 10 % tint | 4.2 | soft/subtle error buttons and badges |
| dark | `--destructive` red-500 `#ef4444` on `--card` `#1e293b` (and on its tint, at 90 %) | 3.4 to 3.7 | outline/soft error buttons, error alerts |

**Fixed without deviating from the kit:** the tabs now look like the kit's (a bordered list, the
current tab on a neutral tint with foreground text; `fcComponentTheme` in the preset), which removes
two of U0's four pairs (muted text on `bg-elevated`, 4.34; white on emerald-600 for the active tab).
The other two U0 pairs (filled primary, subtle success and info) remain and are part of the table.
The **dark** destructive pair is new: U0's gallery never showed error-coloured text in dark.

Fixed in the components on the way: a selected table row keeps readable text (`bg-elevated` with
foreground text, not muted); a table that scrolls sideways sits in a focusable, named region
(`FwListPage`; axe `scrollable-region-focusable`); the row menu is non-modal (a modal Reka menu hides
the page with `aria-hidden` while it stays focusable: `aria-hidden-focus`); the code-chips separator is
slate-500, not the kit's slate-400 (2.56:1 on white; a one-shade deviation in a decorative glyph that
is part of the code's text).

**Toasts were not announced.** Reka UI 2.10.5 (under Nuxt UI 4.11.3) renders its toast announcer with
`aria-hidden="true"` (`VisuallyHidden` with `feature="fully-hidden"`), so the live region is outside
the accessibility tree and nothing is read out; the toast `li` has no live role either. `useFlash`
therefore also announces through two regions of the package (`FwAnnouncer`, rendered by `FwAppShell`,
present from page load: polite for success and info, assertive for warnings and errors), and the
Playwright test asserts the text is in a `status`/`alert` region. To report upstream.

Keyboard and focus, each a Playwright check: the alert dialog traps focus, starts on Cancel, ignores
a mask click, cancels on Escape and returns focus to its trigger; confirmations return focus to the
button; the filters popover returns focus to the Filters button; Clear all moves focus to the search
box; a disabled pager control keeps focus; the toggle group moves with arrow keys; the pick list works
with Tab and Space; the record drawer and form dialog are U2.

## Decisions taken here (reversible)

- `FwTag` is filled, as the kit's `.fc-tag` and badge; Nuxt UI's subtle variant would fail the same
  tokens (2.95 to 3.6) and is not the kit's look.
- The row menu is Nuxt UI's ARIA menu (arrow keys, roving focus), not the kit's popover disclosure;
  it is non-modal, so the page is not hidden while it is open.
- The pick list keeps the kit's checkbox pattern instead of two `UListbox`es (section 10 said
  `UListbox`): checkboxes give the native Tab/Space model the kit specifies.
- Types shared by components live in `src/types.ts`, and two ESLint rules are off for `.vue` files
  (`ui/README.md`, "Rules the lint enforces"); no rule was relaxed for `.ts` files.

## Not verified

Firefox and WebKit were not run. **Screenshots were not approved**: `pnpm gallery:screenshots` writes
44 (every page and the drawer, light and dark, desktop and phone) for the owner's review; no
comparison runs until they are approved and a pinned Playwright container exists. The kit's **text
scale** (a 12.6 px root, `defaultVariants.size`) was not applied: it shrinks every rem-based size by
21 %, and Nuxt UI's small icon buttons would fall under WCAG 2.2's 24 px target size; the gallery runs
at Nuxt UI's 16 px scale (owner decision below). `USkeleton` renders `role="alert"` with
`aria-label="loading"` (Nuxt UI's choice, read in the gallery's accessibility tree; axe accepts it).
In vitest (happy-dom) Nuxt UI's icon component tries to fetch from the Iconify API and is aborted at
teardown (noise, not a failure; the browser build bundles icons).

## Owner decisions

1. **The kit's tokens** (table above): change the light status/primary shades (to 700) and the dark
   destructive red, or accept the pairs. The test's list is exact, so a token change shows at once.
2. **Text scale**: adopt the kit's 12.6 px root (dense, as the platform; needs larger hit areas for
   icon buttons) or keep Nuxt UI's 16 px.
3. **Screenshots**: review and approve the set from `pnpm gallery:screenshots`.
4. Report the Reka toast announcer bug upstream (the package works around it either way).
