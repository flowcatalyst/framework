# Shared UI package: U1 results (2026-10-14, revised the same day)

Milestone U1 of [`../go/ui.md`](../go/ui.md) section 17: the components of section 10 in
`@flowcatalyst/ui`, each with its gallery entry and checks. Built on U0 ([`u0.md`](u0.md), commit
48a545b); the partials, the shell, the composables and `@flowcatalyst/api-runtime` are U2
([`u2.md`](u2.md)). Code: `ui/packages/ui`, gallery: `ui/apps/gallery` (how to run it:
`ui/README.md`). Every claim below is backed by a test in `ui/` unless it says "read in the source".

**Revision (owner rulings 2026-10-14).** The first U1 mapped every ui-kit spec onto a component and
checked a catalog of the 60 specs. The owner ruled that the Nuxt UI app is not a 1:1 mapping of the
Datastar ui-kit: the specs are a checklist of **behaviours** the platform needs, not a visual or API
contract, and Nuxt UI's own components and variants are used instead of re-built ones. The audit and
its result are [`nuxt-native.md`](nuxt-native.md); this page holds what changed in the build, the
behaviour checklist that replaced the catalog, the contrast fix, the licences, and the counts.

## What is built

Five U1 components were deleted because Nuxt UI has them (`nuxt-native.md` has the reasons and what
covers each behaviour now): `FwPageHeader` (`UPageHeader`, themed compact), `FwTag` (`UBadge`),
`FwSpinner` (`UButton :loading`, `UProgress`), `FwEmptyState` (`UEmpty`; the list's filtered variant is
in `FwListPage`) and `FwConfirmDialog` (`useConfirm` opens `FwAlertDialog` through `useOverlay`). Two
were rebuilt as thin wrappers on Nuxt UI: `FwAlertDialog` on `UModal` (with the alert-dialog settings
Reka's `AlertDialog` uses: `role="alertdialog"`, outside clicks prevented, Cancel focused) and
`FwToggleGroup` on `UFieldGroup` + `UButton` (`active` variants) with Reka's `ToggleGroup` behaviour.
`FwStatusBadge` takes Nuxt UI colour names (`colors: { OPEN: "info" }`). The rest stays, as
FlowCatalyst behaviour on Nuxt UI parts:

| Part | What it adds |
|---|---|
| `FwAlertDialog` | an alert dialog on `UModal`: role, label and description, Cancel focused, the mask does not dismiss, Escape cancels, `busy` keeps it open; `close(confirmed)` for the overlay manager |
| `FwToggleGroup` | pressed buttons in a named group, `aria-pressed`, arrow keys, exclusive or independent |
| `FwStatusBadge` | domain status to colour, sentence-case labels, unmapped neutral |
| `FwTableToolbar` | search, size, refresh, Clear all (focus to the search box), Filters popover with the count in its name |
| `FwCursorPager` | Newest / Newer / Older; an unusable control is `aria-disabled` and keeps focus |
| `FwPaginator` | `UPagination` + rows per page + "Showing x to y of n" |
| `FwRowActions` | at most two inline actions named with the row, disabled with a reason, the rest in a non-modal menu, destructive last |
| `FwPickList` | the Manage Roles picker: filter, checkboxes, the picks mirrored with a live count, remove |
| `FwDetailList`, `FwDetailField` | a `<dl>` grid, one column under 640 px of container, "—" for an empty value |
| `FwFormSection` | a section with a real heading at the page's level (2 to 4), danger, card, actions |
| `FwLocalTime` | `<time datetime>` in the viewer's locale and zone, UTC in the title |
| `FwCodeBlock`, `FwJsonBlock`, `FwCodeChips` | code and payloads as text (no `v-html`), focusable named regions, Copy announced; event codes |
| `FwColorModeButton`, `FwAnnouncer` | colour mode without inline styles; the live regions toasts need |
| composables | `useConfirm`, `useDirtyForm`, `useFlash` (kinds now `success`, `info`, `warning`, `error`), `useRequestFailureToasts`, and U2's |

The theme moved from copied kit tokens (`theme/kit.css`) to Nuxt UI's own: `@flowcatalyst/ui/theme.css`
sets only `--ui-*` variables (kit values as the start, checked against `ui-kit/theme/tokens.css` by a
unit test), and component looks are Nuxt UI variants in `fcComponentTheme` (the Vite plugin's `ui`
option): `tabs`, `pageHeader`, `alert`. The shell's sidebar uses the theme's navy palette instead of
hex values. Text scale: Nuxt UI's defaults (owner ruling; the kit's 12.6 px scale is not applied).

## Behaviour checklist

`ui/apps/gallery/src/behaviours.ts` lists **62 platform behaviours**, each with the part that provides
it and the page that shows it: 3 for every page (strict CSP, axe AA, one `<h1>`), 59 on a page. 16 are
provided by a Nuxt UI component used directly (form errors, tables, selects, autocomplete, date range, menus,
tooltip, tabs, modal, popover, empty state, loading, the page header), the others by a FlowCatalyst
part on Nuxt UI. The overview page of the gallery is this table. Two Playwright checks hold it:

1. `e2e/behaviours.spec.ts` opens every page and finds, for each of its rows, an element marked
   `data-behaviour~="<id>"` (and exactly one `<h1>`); ids are unique and pages exist.
2. Each test names the rows it exercises (`covers("drawer-focus", ...)`, a Playwright annotation;
   the ids are type-checked against the list). `e2e/behaviour-reporter.ts` fails a run that includes
   `behaviours.spec.ts` (the full suite) when a row is claimed by no **passing** test. A run of one
   other file is not checked. Checked both ways: the full run prints "all 62 behaviours exercised";
   running `behaviours.spec.ts` alone exits 1 and lists the rows no test exercised.

New tests for rows the earlier suite did not reach (`e2e/native.spec.ts`): the phone sidebar, the
cursor-pagination race in the browser (an older page answers in 600 ms, the first in 60 ms: Older then
Start again keeps page 1), named progress, status badges, section headings, JSON and event codes,
selects by keyboard (single, multiple with search, clearable filter), autocomplete, the menu by
keyboard, the tooltip on keyboard focus, UTable sorting with `aria-sort`, filter, column picker, row
selection and pagination, tabs by arrow keys, modal focus trap and return, popover Escape and return.

## CSP result

Every test ends with `csp.expectClean()`: no `securitypolicyviolation`, no console message about the
policy, no request to another origin, no uncaught page error. **Every page and every overlay is clean
under the strict policy** after the revision too (Chromium 153), including the rebuilt `FwAlertDialog`
and `FwToggleGroup`, `UPageHeader`, `UEmpty`, `UProgress` (its static `style` in Nuxt UI's template is
applied through the CSSOM) and UTable's sorting, filtering, selection and pagination. The U0 probes stand
(`UBanner` with an `id`, `USplitter` drag, asserted to violate it; `UDrawer` clean). Icons named only in
`.ts` files still need listing (`fcIcons`, `nuxtUiOptions({ icons })`); Nuxt UI's own icons (loading,
close, chevrons) are bundled by its plugin from its app config.

## Licences

`pnpm licences` (`ui/scripts/check-licences.ts`) checks the lockfile as before (428 packages, the same
reviewed exceptions) and now also **generates `ui/THIRD-PARTY-NOTICES`** for the shipped bundle and
fails when it is out of date (`pnpm licences:write` rewrites it after `pnpm build`). The shipped
packages are read from the gallery build's source maps (35: Vue, vue-router, Nuxt UI and its runtime
dependencies, Reka, TanStack, Zod, VueUse, floating-ui, `@internationalized/*`, ...) plus what reaches
the bundle without a JavaScript module: the Inter woff2 files, the Lucide icon data Nuxt UI inlines, and
Tailwind's generated CSS. The file lists each package with its licence and carries the full licence text
of each, including:

- **Inter (`@fontsource-variable/inter` 5.3.0): OFL-1.1**, its copyright notice and the full licence text;
- **vaul-vue 0.4.1: MIT from its repository** (`unovue/vaul-vue`), with a note that the npm package
  declares none; the text is copied in `ui/scripts/licences/vaul-vue.LICENSE`;
- Lucide's ISC licence and the Feather MIT notice for the icons derived from it (the npm package
  `@iconify-json/lucide` has no licence file);
- **not shipped**: the MPL-2.0 build and test tools (`axe-core`, `@axe-core/playwright`, `lightningcss`
  with its platform binary), listed as such.

An application regenerates its own with `--dist <its dist> --out <file>`. The upstream request to
vaul-vue is drafted, not posted: [`upstream-vaul-vue-issue.md`](upstream-vaul-vue-issue.md).

## Decisions taken here (reversible)

- Status badges are solid by default (`variant` can be set): every alias passes as a fill under white.
- `FwPickList` keeps checkboxes with the per-checkbox Tab order instead of `UCheckboxGroup` (roving
  focus, no mirrored list); short multi-picks should use `USelectMenu multiple` directly.
- The gallery declares `@tanstack/vue-table` to import `getPaginationRowModel` (Nuxt UI's documented
  way); an application with a paged `UTable` does the same.
- Types shared by components live in `src/types.ts`, and two ESLint rules are off for `.vue` files
  (`ui/README.md`); no rule was relaxed for `.ts` files.

## Not verified

Firefox and WebKit were not run. **Screenshots were not approved**: `pnpm gallery:screenshots` writes 44
(every page and the drawer, light and dark, desktop and phone) into `ui/apps/gallery/screenshots/`
(git-ignored), regenerated after the revision for the owner's review; no comparison runs until they are
approved and a pinned Playwright container exists. Nuxt UI components the gallery does not show
(`UFileUpload`, `UEditor`, `UColorPicker`, `UCarousel`, `UCommandPalette`) were not run under the
strict CSP. `USkeleton` renders `role="alert"` with `aria-label="loading"` (Nuxt UI's choice; axe
accepts it). In vitest (happy-dom) Nuxt UI's icon component tries to fetch from the Iconify API and is
aborted at teardown (noise; the browser build bundles icons).
