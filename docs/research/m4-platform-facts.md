## 2. Dispatch webhook delivery (platform -> app)
Two paths exist. (a) Router -> `POST /api/dispatch/process` callback with mediation payload `{"messageId":"<tsid>"}` (wire-contract.md:191-195,207-210); platform then POSTs the app. (b) The app-facing request is built in internal/platform/dispatchjob/processing/processing.go (buildRequest :~620-690, buildPayload :~760-800).
- Method/URL: POST to the job's `target_url` (= subscription target).
- Headers: `Content-Type: application/json`, `X-Dispatch-Job-Id: <job id>`, `X-Event-Type: <job.Code>`, optional `X-FlowCatalyst-Client: {clientId}:{clientCode}` (only when job has client_id that resolves; omitted otherwise; wire-contract.md:232-240), `Authorization: Bearer <SA webhook auth token>` when resolved, `X-FlowCatalyst-Signature`, `X-FlowCatalyst-Timestamp` — processing.go (buildRequest; headers names const signatureHeader/timestampHeader/clientHeader). Header case on wire is case-insensitive.
- Signature: hex(HMAC-SHA256(key=signing secret UTF-8, msg = timestamp_string + raw_body_bytes)), lowercase hex 64 chars; timestamp = `time.Now().UTC().Format("2006-01-02T15:04:05.000Z")` (ms ISO8601) — processing.go signBody; wire-contract.md:180-205. Signed over body ONLY (client header excluded). Golden vector: tests/golden/webhook/ + pkg/fcsdk/webhook/testdata/ (wire-contract.md:197-201).
- Verifier rules (all three SDKs equal): tolerance 300s past, 60s future, constant-time compare, signature lower-cased before compare, raw header string is what is HMAC'd; unparseable timestamp rejected; bare unix-seconds also accepted; empty secret = fail closed; optional AND-ed bearer gate. Java: WebhookSignature.java:62-63,103-157,183-193. TS: webhook/signature.ts:78-153.
- Who signs (wire-contract.md:220-231, internal/server/delivery_creds.go:57-120): first that NAMES an account, no fall-through: (1) subscription.serviceAccountId, (2) the subscription's CONNECTION's serviceAccountId (normal case), (3) application's oldest active SA via subscription.applicationCode or direct job `app:` code prefix. Named account inactive/without webhook creds => delivered UNSIGNED with a reason (logged, recorded on attempt, appended to errorMessage `(delivered unsigned: ...)` on failure). Creds = serviceaccount.OutboundCreds{BearerToken, SigningSecret, Reason, SignedBy} (P/serviceaccount/secretresolver.go:20-29).
- Body: dataOnly => raw payload bytes (or `{}`); else JSON envelope `{id, type(=job.Code), attemptNumber, source?, subject?, correlationId?, messageGroup?, clientId?, clientCode?(omitted if unresolved), data(parsed JSON, else raw string)}` (buildPayload). `attemptNumber = AttemptCount+1`.
- Timeout: per-job `timeout_seconds` else 30s (processing.go:99-100, deliver ~:548-556); connect/transport timeout => failure "Connection timeout". Response body read capped (maxResponseBody).
- Response classification (exchange(), processing.go ~:830-880; advance() :446-515):
  * 2xx: if body parses as JSON with `ack` present and false => DEFERRAL (parseDeferral): delay = `delaySeconds` (uint32) else 30s; job rescheduled (Reschedule) WITHOUT consuming retry budget. Otherwise (empty/unparseable body or ack true/absent) => success => COMPLETED.
  * 429: deferral, delay from `Retry-After` seconds (else 30s), no budget spent.
  * 401/403: terminal FAILED on first attempt (no retry; owner 2026-09-22 "fail fast"); operator fixes credential and requeues.
  * 422 with header `FlowCatalyst-Outcome: reject`: terminal FAILED immediately (common/message.go:23-35).
  * any other 3xx/4xx/5xx/transport error: counts an attempt; if attempt >= job.MaxRetries => FAILED, else ScheduleRetry with backoff table [5s,15s,30s,60s,120s] clamped at 120s (processing.go:102-111, backoffFor).
- `flushGroup` / mediation response (`ack`,`delaySeconds`,`flushGroup`) in wire-contract.md:255-275 applies to the ROUTER's mediation target (/api/dispatch/process itself), not to the app webhook; the app only needs `ack:false`/`delaySeconds` per above. flushGroup on an app webhook: UNVERIFIED (not parsed by parseDeferral).
- Group ordering: BLOCK_ON_ERROR subscriptions hold later jobs of a message group after a failure (processing.go:284-312, memory dispatch-group-ordering); app should return 2xx quickly.
- Existing receivers to port: TS webhook/signature.ts (171 lines; function `verifyDeliverySignature`, error codes); LV Webhook/WebhookValidator.php (143), Webhook/BearerTokenCheck.php (40), Http/Middleware/ValidateWebhookSignature.php (52), Exceptions/WebhookValidationException.php (64), Console/Commands/VerifySignatureCommand.php (103). Java already has the equivalent (WebhookSignature, 214). Go: pkg/fcsdk/webhook/{validator.go,webhook.go}. NONE of TS/Laravel implements a generic dispatch-job route returning `{ack}`; they only verify the signature and leave the handler to the app (UNVERIFIED for example apps).
