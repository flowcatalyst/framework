# Languages and locale formatting (JTE)

> **Optional, with `framework-ui`.** Built 2026-11-03 to the contract
> [`contracts/i18n.md`](../contracts/i18n.md) (plan and reasoning: [`i18n-plan.md`](../i18n-plan.md)). The
> mechanism is the same in the Go kit ([Go: languages](go/i18n.md)); both read one shared catalog,
> `ui-kit/messages/<tag>.json`. English is the source, the default and the fallback of every message; Afrikaans
> ships as the showcase. API error bodies do not change: they keep their code and English `message`.

## What it does

- **Catalogs**: one flat JSON file per language, message key to message. A message is a string or a plural object
  whose keys are CLDR categories (`one`, `other`, ...; `other` is required). Placeholders are `{name}`; a doubled
  opening or closing brace is a literal brace; nothing else is syntax (no ICU MessageFormat).
- **Lookup**, per key: the locale's tag (`af-ZA`), then its language (`af`), then `en`. A key no catalog has renders
  as itself, and the tests fail on it.
- **Layers**: the kit's catalog, then the application's catalogs on top. Within one tag the top layer wins, so an
  application can override a kit message in a language it ships; an English override never beats the kit's
  Afrikaans for an Afrikaans user.
- **Plurals**: the category is chosen from the argument `count` (an integer or a decimal) by the CLDR rule of the
  language the message came from: `en` (one when the number is exactly 1 with no fraction digits), `af` (one when
  n = 1, so `1.0` too), `zu` (one when the integer part is 0 or n = 1). Any other language uses `en`'s rule.
  No `ResourceBundle` is involved.
- **Locale of a request**, once: the user's preference, the tenant's default, `Accept-Language` by quality, then
  `en`, keeping the first that names a language the application supports.

## Wiring it

`Views.Builder` takes the resolver and the application's catalogs; `Views` resolves each request, writes the
resolved tag into `<html lang>`, and renders the page, its flash messages and its Datastar patches with that
request's messages (the kit's templates read them from `Messages.current()`, a scoped value `Views` binds):

```java
Views.builder(ASSETS)
    .locales(LocaleResolver.builder().supported("en", "af").user(r -> r.header("X-User-Locale")).build())
    .catalogs(
        Bundle.kit()
            .with(Map.of("af", Catalog.parse("{\"flash.saved\": \"Gestoor.\"}"))))
    .build();
```

(from `ViewsI18nTest`; a real application reads the principal's `locale` in `user` and the client's default in
`tenant`, and loads its catalogs from `i18n/<tag>.json` with `Bundle.loadClasspath`.) Without `locales(...)` pages
are English. In a handler, `views.messages(request)` gives the request's `Messages`:

```java
Bundle.kit().messages("af").t("kit.paginator.showing", Map.of("from", 1, "to", 10, "total", 55, "noun", "rye"));
// "Wys 1 tot 10 van 55 rye"
```

(from `I18nTest`.) A plural message takes `count`: `messages.t("kit.list.rows", Map.of("count", n))`.

## The kit

Every user-visible string of the kit's templates (labels, aria-labels, titles, placeholders, dialog and pager text,
the defaults of label props, the generic flash fallbacks) is a `kit.` message. A prop that sets a label wins over
the catalog (`Props.AlertDialog` with `cancelLabel` set keeps it in every language). English output is unchanged
from before: the fixtures still pass byte for byte after normalisation.

Texts that end up inside a Datastar expression (the password toggle's labels, the strength words, the multi-select
chips' remove label) are quoted for JavaScript by `Kit.jsq` and `Kit.jsMessage`. A text with markup in it (the
secret reference help, the permission line of the permission-denied dialog) is written by `Kit.htmlMessage`, which
escapes the message and splices in only the markup the template passes for named placeholders.

Two texts are not translated: the logo's `aria-label` (the brand, `FlowCatalyst`) and the islands' own scripts
(`fc-diagram.js` says "Rendering diagram...", CodeMirror has its own phrases); both are pinned third-party or
generated assets.

## Validation and flashes

- `messages.validation(code, params, message)` returns `validation.<CODE>` with the error's parameters as arguments;
  it returns `message` (the error's own English text) when no catalog has the key or the text needs a parameter the
  error did not carry. Every code of `Rules` has a key in `en` and `af` (`NOT_NULL`, `NOT_BLANK`, `TOO_SHORT`,
  `TOO_LONG`, `PATTERN`, `OUT_OF_RANGE`, `SIZE`, `NOT_ONE_OF`). Rule violations carry no parameters yet, so a
  parameterised text falls back to the English message until they do (see the STATUS notes).
- A flash registered with `Views.Builder.flash` is shown from `flash.<key>` (its summary) and `flash.<key>.detail`
  (its detail) when the catalogs have them, else as registered.

## Dates, numbers, money, quantities

The server writes plain values and the browser formats them with `Intl`, in the language of the page:

| Component | Server text | Browser |
|---|---|---|
| `Kit.localTime` (existing) | UTC instant | `toLocaleString(document.documentElement.lang)` |
| `Kit.localNumber` | the plain decimal | `Intl.NumberFormat`, keeping the value's fraction digits |
| `Kit.localMoney` | `3132.48 ZAR` | currency style, the currency's minor units unless `digits` is given |
| `Kit.localQuantity` | `12.5 kg` | the number formatted, the unit symbol after it |

The three new components take plain strings (`Props.LocalMoney` an amount and a currency code, `Props.LocalQuantity`
a value and a unit symbol), so they depend on no money or units type. A value that is not a plain decimal, or a
currency that is not three capital letters, is refused at render time like every kit input. There is no server-side
locale data.

## Checks

`I18nTest` and `KitI18nTest` assert: every key of `af` exists in `en` with the same placeholders and plural-ness,
every kit fixture renders with no message missing in `en`, `af`, `af-ZA`, `zu` and an unknown language (a missing
key would render raw), English output shows no key, every key the sources use is in `en` and every English kit key
is used, plural objects have `other`. `untranslatedReport` prints the English keys a catalog lacks (not a failure).
`I18nConformanceTest` writes `conformance/i18n/cases.json` (lookup, fallback, placeholders, plurals, resolution,
validation), which the Go package compares.
