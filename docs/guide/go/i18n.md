# Go: languages and locale formatting (templ)

> **Optional, with `go/ui`.** Built 2026-11-03 to the contract [`contracts/i18n.md`](../../contracts/i18n.md); the
> Java counterpart is [Languages (JTE)](../i18n.md) and has the rules in full. Package `go/ui/i18n`, standard library
> only; the kit's catalogs are `ui-kit/messages/<tag>.json`, copied into the package (`go/ui/i18n/messages`) by
> `make -C go go-sync-shared`, which the conformance test guards byte for byte (`//go:embed` cannot reach outside
> the module).

## Using it

```go
h := i18n.Middleware(i18n.Config{Supported: []string{"en", "af"}})(next)
// in a handler or a templ component, with the request's context:
i18n.T(ctx, "kit.paginator.showing", i18n.Args{"from": 1, "to": 10, "total": 55, "noun": "rye"})
```

`Config` also takes `User` and `Tenant` (functions of the request returning a tag, or "") and `Bundle` (the
application's catalogs over the kit's). The resolved tag is `i18n.FromContext(ctx)` (`en` when nothing was resolved);
`i18n.T` reads the locale and bundle from the context and falls back to the kit's English messages, so a component
rendered with a bare context still works. Application catalogs are read with `i18n.LoadFS(fsys, "i18n")` (files
`i18n/<tag>.json`) and layered with `i18n.Kit().With(layer)`.

`views.New` takes the same configuration as an option, for an application that does not run the middleware:

```go
views.New(a, views.WithLocales(i18n.Config{Supported: []string{"en", "af"}, Bundle: bundle}))
```

(from `views/i18n_test.go`.) The views then resolve each request, set `<html lang>` to the tag, render the page, its
flash messages and its patches in that language, and `Views.Context(r)` gives a handler the same context. A locale
the middleware already stored is kept.

## What differs from the Java page

- The kit's components get the request through the templ `ctx`; a label prop still wins (`orDefault(p.CancelLabel,
  i18n.T(ctx, "kit.dialog.cancel"))`). `MultiSelectProps.Summary()` stays English; `SummaryFor(ctx)` is the localised form.
- Texts in Datastar expressions use the unexported `jsq` and `jsMessage`; texts with markup use `htmlMessage`.
- `i18n.Validation(ctx, code, params, message)` is the field-error helper (the fallback rules are Java's).
- `i18n.Bundle.OnMissing` reports a lookup no catalog answers; the kit's tests use it to fail on a raw key.
- Checks: `i18n_test.go` (catalog consistency, validation codes, the report, resolver, middleware), `conformance_test.go`
  (the shared vector `conformance/i18n/cases.json` the Java kit writes), and the kit's `i18n_test.go` (every fixture
  renders in five locales without a missing message, label props win, every key used exists and every key is used).

## Formatting

`kit.LocalTime` formats with `document.documentElement.lang`; `kit.LocalNumber`, `kit.LocalMoney` (`Digits *int`) and
`kit.LocalQuantity` write the plain value as the element text and the browser formats it, exactly as in Java (specs
`ui-kit/components/local-number.md`, `local-money.md`, `local-quantity.md`; fixtures `ui-kit/fixtures/local-*`).
