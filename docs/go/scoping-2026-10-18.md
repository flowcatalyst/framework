## 1. Headline

- The brief assumed Go starts around G5; it does not. **G0 to G6 are built** (core, config, locks, write
  path, checked SQL, HTTP, OpenAPI, SPA, rate limiting, HTTP client, secrets, FlowCatalyst module and
  receivers, sessions and login, orders-demo on sessions, the admin). The orders browser suite on the Go
  server: 48 passed, 4 skipped, 1 failed of 53 (Java: 49 passed, 4 skipped); the one failure is a
  sign-out URL assertion that depends on a Java launcher behaviour contract I1 forbids.
- What is **missing** is almost entirely what Java added on **2026-10-17 and 2026-10-18** after the Go
  plan was written: `load` + `authorizeLoaded`, joining the caller's transaction, `Context.forClient` +
  `PerClient.each`, M5 client settings, and the M4f trial service (G7). Everything older is built.
- Shared vectors cover storage and wire shapes well. Behaviour (runner failure table, rate limiting,
  secrets, signatures, errors, health, metrics, sessions beyond sign-in failure) has **no vector**: Go
  follows Java by reading.

## 5. What blocks on the platform

- **Per-client secrets** (`platform` driver): no platform endpoint resolves them; also the platform-config
  read returns SECRET values unmasked to any anchor-tier caller. Both frameworks fail start-up on it.
- **Dispatch job `clientCode`**: `/api/dispatch-jobs/batch` stores `clientId` unresolved, so jobs are
  platform-scoped unless given the platform's client id. Affects the tickets notify flow (G7.6).
- **Receiver audit rows carry no causation field**; the dispatch job id reaches events but not audit rows.
- **Per-client scheduled-job firing**: owner ruled the application fans out (so `PerClient.Each`, no platform work).
- **Sessions**: no platform token kept or refreshed (revalidation not possible); issuer must be reachable at
  one URL (no internal URL); contract I1 (end-session redirect) differs between Go and the Java launcher.
- **The real-platform end to end** is cheap for Go because the platform and `fcdev` are Go and local. The
  platform half of G4's check and the sessions/admin runs were not made against a real platform.
- Nothing in G7.2 to G7.5 needs the platform.

## 6. Owner decisions (8, each with a recommendation)

1. **Build the tickets trial in Go (G7) as the parity gate?** Recommend yes: it proves the 2026-10-18
   additions end to end, reuses `ui/apps/tickets` unchanged, and gives the byte-for-byte OpenAPI check.
   Measurements (design decision 34) can wait until it runs.
2. **Load-phase API shape.** Options: add `Load`/`AuthorizeLoaded` methods to the four-method interface
   (every use case implements them) or a second interface, `LoadedUseCase[C,E,L]`, with its own `Define`.
   Recommend the second: plain use cases are unchanged and "missing Authorize does not compile" survives.
3. **Tx join API.** Recommend `Runner.RunJoined(ctx, cx, uc, cmd, joined)` where `joined` is a framework
   value that only `Once` (or a framework helper) can build, so `database.Tx` stays framework-constructible
   and a caller cannot hand in an arbitrary connection.
4. **Client settings in Go: same table and JSON, now?** Recommend yes, same `fw_client_settings` and
   `[a-z][a-z0-9._-]{0,99}` keys, so a Go service can take over a Java database; accept the contract's
   section 7 rulings (one row per client, no cache, an undecodable value is an error) as provisional.
5. **May Java tests write the missing vectors first?** Recommend yes for signatures/receiver responses,
   runner scenarios (failure table, load, join), client settings and rate limiting; a mismatch is then a
   Go bug or a reported Java bug, as the conformance README says. Skip metrics/health text for now.
6. **Publishing and CI.** Nothing is tagged; `go.yml` has never run. Recommend run CI now (G7.0), keep the
   Go module path and package names as working names, and tag only after G7.7.
7. **Real-platform gate.** Recommend G7.7 as the exit criterion for "Go is production-credible", ahead of
   measurements, since the platform is local Go.
8. **Close MA 2 (test overrides) and MC as n/a for Go**, and keep `about.framework` omitted unless a
   vector demands it. Recommend yes to both: `build(...)` parameters replace overrides, MC is Java-app
   specific, and a version constant is a one-line add if Java's UI needs it.
